Response Time — how this is calculated

What this measures

Per incident: the time between when it happened (issue_occurred_at) and when a NOC engineer picked it up (take_in_progress_at). MIN/AVG/MAX are computed across every incident in that week.

% change formula

min( |last week − this week| ÷ last week × 100, 100 )

Example: last week = 4m, this week = 3m
|4 − 3| ÷ 4 × 100 = 25%
3 ≤ 4, so it improved.

Example — sub-minute baseline

old (last week MIN) = 3.19s ≈ 0.0532 min
new (this week MIN) = 2s    ≈ 0.0333 min

raw_pct = |0.0532 − 0.0333| / 0.0532 × 100 = 37.3% → rounds to 37
capped  = min(37, 100) = 37        (no capping needed, already under 100)
improved = 0.0333 ≤ 0.0532 → True  (faster this week = good)

The % is always run through min(pct, 100) — so a tiny baseline (a single near-instant incident, for example) can never inflate into a meaningless number in the thousands, no matter how small it is relative to this week's value.

Resolution Time — how this is calculated

What this measures

Per incident: the time between when it happened (issue_occurred_at) and when it was actually resolved (resolved_at). MIN/AVG/MAX are computed across every incident in that week.

% change formula

min( |last week − this week| ÷ last week × 100, 100 )

Example: last week = 4m, this week = 3m
|4 − 3| ÷ 4 × 100 = 25%
3 ≤ 4, so it improved.

SLA Compliance — how this is calculated

What this measures

Every incident has a response deadline and a resolution deadline. This card shows the percentage that beat each deadline — using Streamline's own recorded pass/fail (overdue_response / overdue), not a guess calculated here.

Response SLA Met

Every incident counts. Example: 730/738 means 738 incidents happened this week, and 730 of them got a response before their deadline → 730 ÷ 738 = 99%.

Resolution SLA Met

Only incidents Streamline actually gave a verdict on count — some incidents (often closed a different way) are left blank by Streamline and are excluded rather than guessed at, so the bottom number here is usually smaller than the total incident count. Example: 274/288 means 288 incidents had a real pass/fail verdict, and 274 passed → 95%.
