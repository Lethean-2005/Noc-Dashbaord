Getting Started with Noc-Dashboard

Noc-Dashboard is an internal, browser-based monitoring dashboard that gives NOC staff a single, always-current view of network alarms, incidents, site status, and partner contacts. There is no login step — opening the dashboard's URL goes straight to live data, read from a local cache that background jobs keep in sync. This page walks through every area of the app; use the sidebar to jump straight to one.

Getting Started

There is no login step — opening the dashboard's URL goes straight to live data.

  • The sidebar switches between the five pages: Overall Dashboard, Custom Dashboard (Reports), Map View, Mentor Site, and Partner Contact.
  • Search Cards in the topbar jumps straight to any card on the current page by name.
  • Every colored badge number is a live count — click it, its label, or its bar/dot to open a filtered drilldown table.

See the User Demo Guide under Downloads for a screenshot-by-screenshot walkthrough of every page.

Where the Data Comes From

Every page reads from a local cache — never live from MSSQL or PostgreSQL directly — so pages load instantly and the two source databases only ever see a small, steady stream of background sync queries.

  • MSSQL is the source for ISP POP / EZE / TCT / IT NODE alarms, On-Air site master data, POP data, VIP/VVIP sites, and Partner Contact.
  • PostgreSQL (Streamline) is the source for Incidents, INC-WOs, the broader alarm feed, and Planned/Other site master data.
  • On-Air site status comes from MSSQL specifically because it reflects real network inventory more directly and updates sooner than Streamline's own status field — the two sources are kept independent rather than merged, so if they ever disagree about a site, the Map shows both instead of silently picking one.
  • Full technical detail — every query, every cache table, and the Cambodia Province/District/Commune/Village hierarchy — is in the Query & Data Reference PDF under Downloads.

The Topbar Toolbar

  • Refresh reloads the page immediately instead of waiting for the next background sync.
  • Theme switches between Light and Dark — saved in the browser, applied instantly, no reload.
  • Card Layout lets you reorder dashboard cards (Default, same for everyone, or Custom, drag-to-reorder) — independently for the Overall and Custom Dashboard pages.
  • Fullscreen toggles the browser's fullscreen mode.

See the User Demo Guide under Downloads for a screenshot of each of these, including the Card Layout modal and dark mode.

Dashboard

Each card's badge shows a live count. Click any badge to open its drilldown table.

  • IP Ezecom combines ISP POP badges (POP DOWN, POP POWER) with Ezecom's own alarm badges in one card; IP Telcotech/Cellcard is the same idea for TCT — both are MSSQL-sourced, alongside VVIP Site and Mentor Site.
  • RAN Status has four independent badge groups side by side — Site Down, Main AC Alarm, DC Low/High, and Tech Down — each with its own View button and a Hub-Site/Diamond/Gold/Silver/Bronze grade breakdown.
  • Incident / INC-WO by Status shows Incident and INC-WO badge groups side by side, each with its own View button.
  • Three chart cards summarize trend data: Incident Age, Incidents Closed, and Incident Volume. Every bar, dot, or segment on them is clickable the same way a badge is, and hovering shows an exact-value tooltip first.
  • The Incidents Closed and Incident Volume drilldowns support a Filter by Category checkbox control — only categories actually present in that table are listed. Checking more than one category shows rows matching any of them, and the export respects the same selection.
  • Incident Age – Open's own count still opens the usual drilldown table, but each bar also has its own worklog icon (, next to the count) — click it to see every currently-open incident in that age bucket, each one expandable to its own real worklog history (comments and status/field changes pulled straight from the source system) without leaving the dashboard.

Map View

  • Use the status filter (top left) to switch between On Air, Planned, Other, and Site Down, or a specific vendor under On Air.
  • Search by site code, POP code, or village name using the search box.
  • Draw a boundary by searching a province, district, or commune to see a scoped list and export.
  • Clicking any site or POP dot opens a popup with its name, status, and — for a site with an open Site Down incident — a direct link to that incident.
  • The map refreshes itself automatically — no manual reload needed for status or Site Down changes on sites already shown.

Partner Contact

  • Use Add Partner to create a new partner with its first contact in one step.
  • Use a row's Add Contact button to attach another contact to an existing partner — this never creates a duplicate partner record.

Backed directly by MSSQL (TBL_PARTNER, TBL_PARTNER_CONTACT) — every query behind this page is in the Query & Data Reference PDF under Downloads.

Reports & Exporting

The Custom Dashboard (Reports) works exactly like the Overall Dashboard — live badge counts with their own drilldowns — combining eight cards onto one page: Current Site Down, Alarm Site Down, Alarm Completely Site Down, Alarm Main Failure, INC-WO Site Down, Alarm DG On, INC-WO Resolved, and IT NODE.

Every drilldown table, the Map, and Reports each have their own export control — CSV for tabular drilldowns, styled .xlsx for the Map and Reports.

See the User Demo Guide under Downloads for a screenshot of this page.

Incident Report

A fillable, exportable incident report document matching the standard Wholesale Products & Service Delivery template — editable fields laid directly on the page instead of a separate form. Saved reports switch via a dropdown at the top instead of a list page.

  • Save as Draft saves whatever's filled in so far, skipping required-field checks. Save & Complete enforces them, then marks the report Final.
  • Export as PDF or DOCX — both match the same reference template exactly, generated from the same saved data.
  • Chronology of Events — each event has its own date and time, so a chronology that runs past midnight still shows which day every line belongs to. A "Date and Time: <date>" header appears automatically above the first event of each day (not repeated on every line), the same grouping the exported document itself uses. Typing or picking events out of order re-sorts them into the correct chronological position automatically once you finish editing that row — no need to re-order anything by hand.
  • Use + Add Event to add a new row at the end, or the small on any existing row to insert a new one directly underneath it — useful when you realize an event is missing from the middle of an already-typed chronology.
  • Picture Reference photo uploads accept phone-camera photos directly, including the HEIC format iPhones save by default — every upload is automatically normalized to a standard format before being embedded in the exported document.

Notifications & Alerting

Background alert jobs watch the same local cache every page reads from — nothing here puts extra load on MSSQL or PostgreSQL. Bot tokens and chat/group IDs live in the app's environment file; the destinations below are illustrative labels for the role each one plays.

Four independent bots run on their own schedules, each posting to its own chat as a table image with a styled .xlsx attachment, falling back to plain text if image rendering isn't available.

Technology Stack

Backend

  • Flask web framework, Jinja2 templates.
  • SQLAlchemy + psycopg2 for PostgreSQL, pymssql for MSSQL.
  • SQLite (WAL mode) local cache, Waitress production server.

Frontend

  • Leaflet for map rendering, Tabler Icons throughout.
  • Vanilla JavaScript — no frontend framework.

Export & Alerting

  • openpyxl for spreadsheet export, Pillow for alert table images.
  • Telegram Bot API and Teams incoming webhooks, both plain HTTP.

See the Feature Report PDF under Downloads for the full architecture behind this stack.

Mentor Site

Flags specific sites for focused monitoring, independent of their normal status.

  • Use Download template to get a blank CSV with the right site_code column header, then use Import File to bulk-add sites from it.
  • Use Input Site Codes to add one or more sites by typing their codes directly — space-separated to add several at once.
  • Use View Alarms to open the alarm drilldown scoped to only the configured mentor sites.
  • Monitors the same alarm types as the Dashboard's other cards: Site Down, Main AC Failure, Low/High DC Voltage, DG-On, RECT Failure, Door Alarm, and Other.

See the User Demo Guide under Downloads for a screenshot of this page.

Troubleshooting

For questions about a specific card's logic, data source, or an unexpected count, check the relevant drilldown's date filter and export first. Most apparent discrepancies trace back to a sync-timing window (every background job refreshes every few minutes, not instantly) rather than a data error.

Still stuck? The Query & Data Reference PDF under Downloads explains exactly which query and cache table feeds each card, and the Virtual Machine Setup Guide covers dependency and startup issues.
